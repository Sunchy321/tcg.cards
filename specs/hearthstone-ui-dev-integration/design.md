# 炉石 UI 合入最新 dev 设计方案

## 背景

`sub` 分支包含一套已经完成视觉调整的炉石页面，但 `dev` 后续新增了账号设置、公告、时间线、新卡图组件、新高级搜索 Slideover，以及新的服务端查询和数据模型。直接采用任一分支的完整文件都会丢失另一侧的重要能力。

本次整合的目标不是删除 `sub` 的炉石改动，而是把其中仍然成立的 UI 设计移植到最新 `dev` 结构上。

## 目标

- 保留 `dev` 的账号设置、登录状态、公告、时间线和现有导航入口。
- 保留 `dev` 的服务端接口、搜索 DSL、卡图路径、共享组件和数据库访问逻辑。
- 将 `sub` 的炉石视觉设计应用到最新页面，包括主题、首页入口、搜索结果、卡牌详情、卡包列表、职业图标、系列图标和数值展示。
- 保持当前线上炉石导入数据、数据库 schema 和迁移历史不变。
- 让炉石站在类型检查和构建通过后再进入 PR。

## 非目标

- 不恢复已经被 `dev` 替代的旧高级搜索独立页面。
- 不恢复旧版 CardImage、旧服务端搜索实现或旧 oRPC 路由。
- 不修改炉石 schema、炉石迁移、导入任务或发布任务。
- 不在本次整合中调整游戏王或影之诗实现。
- 不把临时测试脚本、`old_card_part1.txt` 或 `out.html` 带入 PR。

## 来源优先级

| 范围 | 主要来源 | 处理方式 |
| --- | --- | --- |
| 账号设置、认证、用户配置 | `dev` | 完整保留 |
| 服务端接口、搜索、数据模型 | `dev` | 完整保留 |
| 卡图加载与共享 CardImage | `dev` | 保留新组件，只迁移外层视觉 |
| 高级搜索功能 | `dev` | 保留 Slideover 和现有查询参数 |
| 首页、搜索、详情、卡包视觉 | `sub` | 按最新页面结构重新移植 |
| 炉石主题和颜色变量 | `sub` | 与 `dev` 新变量逐项合并 |
| 职业图标、系列图标 | `sub` | 保留资源，确认引用后再纳入 |
| 国际化文案 | 两者 | 保留 `dev` 新键，只补充 UI 所需键 |

## 页面整合方案

### 首页

保留 `dev` 的账号设置、公告入口和当前 Header 行为，把 `sub` 的炉石主题、入口卡片层级和视觉样式移植到现有首页。高级搜索入口继续打开 `dev` 的 Slideover，不恢复 `/search/advanced` 独立路由。

### 搜索与高级搜索

保留 `dev` 的查询 DSL、排序、布局切换、用户配置同步和最新版本视图。将 `sub` 的筛选层次、职业与系列图标、卡片密度和视觉反馈移植到当前搜索页面及 Slideover。

### 卡牌详情

保留 `dev` 的公告关联、版本信息、英雄技能、render model 和共享卡图组件。移植 `sub` 的属性排版、文字层次、护甲显示、可用赛制与响应式布局。

### 卡包列表

保留 `dev` 当前数据来源和路由，移植 `sub` 的系列图标、分组方式和列表视觉。不得把静态图标存在视为替代服务端数据。

## 数据安全边界

- 最终 PR 相对 `upstream/dev` 不得包含 `packages/db/src/schema/**/hearthstone` 差异。
- 最终 PR 不得包含炉石 migration 差异。
- 最终 PR 不得包含 `apps/service-desktop-runtime/src/lib/hearthstone` 差异。
- 最终 PR 不得改变数据库连接优先级。
- 炉石服务端文件默认恢复为 `dev`；只有前端确实需要且经过单独验证的兼容改动才可保留。

## 合并策略

1. 以当前 `MERGE_HEAD`（`upstream/dev`）作为功能基线。
2. 清理自动合并带回的旧炉石后端、调试文件和部署配置。
3. 从 `ORIG_HEAD` 逐页提取 UI 意图，不直接整文件覆盖新版页面。
4. 每完成一个页面立即运行对应类型检查，并对比关键交互。
5. 最终以 `git diff --cached MERGE_HEAD` 审核实际 PR 范围。

## 验收标准

- 账号设置入口和用户配置同步仍可使用。
- 首页、高级搜索、搜索结果、卡牌详情、卡包列表体现 `sub` 的炉石 UI。
- 高级搜索仍使用 `dev` 的 Slideover 和查询逻辑。
- 公告、时间线、随机卡牌、语言切换和明暗模式仍可使用。
- 最终差异不包含炉石 schema、迁移、导入任务或数据库连接逻辑。
- `bun install --frozen-lockfile` 使用仓库指定 Bun 1.3.10 成功。
- `bun --filter site-hearthstone typecheck` 和构建通过。

## PR 拆分建议

- 炉石 UI 适配单独一个 PR。
- 影之诗单独一个 PR。
- 游戏王站点、导入流程和数据库迁移单独一个或多个 PR。

拆分后即使某个站点需要继续调整，也不会阻塞其他站点或扩大线上回归范围。
