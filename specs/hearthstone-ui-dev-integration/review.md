# 炉石 UI 合入最新 dev 设计评审

## 评审结论

方案已获确认，可以进入实现。实现必须以最新 `dev` 的功能、接口和数据结构为基线，只迁移 `sub` 中仍然成立的炉石视觉设计，不得用旧页面整文件覆盖新页面。

## 已确认的关键决策

- 账户设置、登录状态、用户配置、公告、时间线和现有导航入口保留 `dev` 实现。
- 高级搜索保留 `dev` 的 Slideover、查询 DSL 和参数同步，只调整视觉层。
- 卡图继续使用 `dev` 的共享组件、变体判断和路径规则。
- 首页、搜索结果、卡牌详情和卡包列表吸收 `sub` 的主题、信息层级、图标与卡片样式。
- 炉石服务端、数据库 schema、迁移、导入任务和发布任务不属于本次 UI 整合范围。
- 影之诗、游戏王与炉石 UI 应拆分审查，避免一个 PR 同时承担多个站点及数据迁移风险。

## 主要风险与处理

### 功能回退

旧 UI 文件与新功能文件存在同名冲突。实现时逐个组件移植样式，并以 `MERGE_HEAD` 的交互和数据绑定作为不可退化基线。

### 数据风险

当前合并曾夹带数据库连接优先级、服务端搜索和临时脚本改动。实现前恢复这些文件为 `dev` 版本，并在最终差异中确认不存在炉石 schema、迁移、导入和发布改动。

### 视觉失真

直接套用通用卡片模板会削弱用户已经认可的炉石风格。实现以 `sub` 现有图标、色彩、材质和页面层级为准，不增加无来源的装饰图标或通用渐变。

### 验证环境

仓库工作流固定 Bun 1.3.10，本机 Bun 1.3.12 无法可靠执行冻结锁文件安装。最终验证应优先使用仓库指定版本；若本机暂时无法取得该版本，必须如实记录未通过的检查，不能以当前版本改写锁文件。

## 通过条件

- `dev` 新增功能和路由均保留。
- 炉石核心页面能够辨认出 `sub` 的既有 UI 方向。
- 高级搜索仍走 Slideover，账户设置和公告入口仍可用。
- 最终差异不存在炉石数据结构、迁移、导入、发布或数据库连接变更。
- 类型检查和构建使用仓库规定的依赖版本完成，或明确记录真实阻塞原因。

## 实施后复核

- 炉石首页、搜索、高级搜索、卡包列表、账号设置、浅色与深色主题均已在本地服务中检查，高级搜索条件交互正常。
- 详情页保留 `dev` 的共享卡图、版本、公告和相关卡牌实现；本地数据未提供可访问的卡牌编号，因此未完成带真实卡牌数据的视觉复核。
- Bun 1.3.10 冻结锁文件安装通过。类型检查和构建的既有阻塞已记录在实施计划中，不将其误报为通过。
- 炉石数据库连接、schema、迁移、导入服务和发布服务相对 `MERGE_HEAD` 无额外差异；提交代码本身不会执行线上导入或改写线上数据。
