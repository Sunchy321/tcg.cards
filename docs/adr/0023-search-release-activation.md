# 0023: Activate search releases independently by storage

Each game's PostgreSQL projection and Magic query-routing reference data, D1 snapshot, and R2 base-plus-locale package group activate atomically within their own store, without a cross-store release barrier. This keeps one failed destination from blocking unrelated stores, at the cost of temporary version differences: D1 must fall back to PostgreSQL when either its logical data version or `releaseHash` differs, and local results may open newer online details. The public manifest is a mutable per-game pointer, while SQLite objects use immutable SHA-256 addresses so identical files can be reused and safely CDN-cached; `releaseHash` binds the PG projection fingerprint, all package hashes, schema version, and routing metadata while remaining separate from logical `dataVersion`.

The active PostgreSQL identity and Magic routing metadata live together in one shared public table, with one row per game. Chunked projection publishing sets that row unavailable before changing search rows and activates the matching fingerprint and routing metadata only after the publish completes. Requests use the original PostgreSQL search path while the row is unavailable.
